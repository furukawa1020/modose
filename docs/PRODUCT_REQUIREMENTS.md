# MODOSE プロダクト要件定義

- 文書状態: 実装基準
- 製品名: MODOSE
- タグライン: 現実に Ctrl+Z を。
- 対象プラットフォーム: ARCore対応Android端末
- 主言語: Kotlin / Rust / Go
- TypeScript: 使用禁止
- 物理アクチュエータ: 使用禁止

---

## 1. プロダクト定義

MODOSEは、スマートフォンで保存した卓上の物体配置と現在の状態を比較し、元の位置に表示する半透明の残像、現在位置から目標位置へ向かう矢印、向きの修正指示を使って、人の手による現実の復元を支援するアプリである。

MODOSEが直接物体を動かすことはない。VLMが意味上の物体同一性と状態を判断し、ARCoreと端末内処理が現実座標への接地とリアルタイム表示を担い、人が実際の操作を行う。

### 1.1 一文での説明

> スマホで机を保存し、物を動かしたあとにカメラを向けると、元の位置へ戻すための残像と矢印が現れる。

### 1.2 呼称

使用する:
- VLMを使った現実復元カメラ
- AR復元ガイド
- Human-in-the-loopな視覚行動ループ

使用しない:
- VLA
- OS
- コンパイラ
- 自律ロボット
- デジタルツイン

## 2. ユーザーに約束する範囲

### 2.1 対応する環境

- 平坦な卓上または床面
- 室内の通常照明
- 背面カメラ
- 縦画面
- 1〜5個の物体
- 物体サイズの目安: 3 cm〜35 cm
- 対象範囲の目安: 30 cm四方〜100 cm × 70 cm
- 保存から復元完了まで同一ARCoreセッション
- 自動物体理解にはネットワーク接続が必要
- VLM解析完了後のARガイドは一時的な通信断でも継続可能

### 2.2 対応する物体

- 剛体または形状がほぼ変化しない日用品
- 不透明または半透明度が低い物
- 互いに見分けられる外観を持つ物
- 例: ペン、鍵、財布、カード、ノート、マウス、USBメモリ、カップ、菓子箱、イヤホンケース

### 2.3 対応する変化

- 卓上での移動
- 卓上平面内での回転
- 画面外への一時的な移動
- 1個までの部分的な重なり
- 元に無かった物体の追加
- 対象物体の不足

### 2.4 非対応

- 同じ外観の同一製品が複数ある場面
- 透明物、鏡面物、強い反射物
- 布、ケーブル束、液体など形状が大きく変わる物
- 物体の裏返し
- 分解・組立による形状変化
- 6個以上の同時復元
- 暗所、強い逆光、激しいカメラ移動
- 保存後にアプリを終了してからの復元
- 別端末からの復元
- 部屋全体や棚全体の復元
- ミリメートル精度の配置
- 安全・医療・法的判断への利用

## 3. 成功体験

### 3.1 標準デモ

1. ユーザーがアプリを開く
2. 「机をゆっくり映してください」と表示する
3. 水平面と追跡品質が十分になると「保存」が有効になる
4. ユーザーが1〜5個の物体を置き「保存」を押す
5. VLMが対象物体を検出し、番号付きの枠と名称を表示する
6. ユーザーが不要物体を除外できる
7. 「この状態を保存」を押す
8. 「好きに動かしてください」と表示する
9. 審査員が物を移動・回転・一時的に隠す
10. ユーザーが「戻す」を押す
11. VLMが現在の物体と保存物体を対応付ける
12. 1個ずつ、目標位置の残像と移動矢印を表示する
13. 物体を戻すと短い振動とチェックを表示する
14. 全物体が局所条件を満たすと最終画像をVLMで再確認する
15. 成功時に `REALITY RESTORED` を表示する
16. 失敗時は、合っていない物体だけを再提示する

### 3.2 「おお」となる瞬間

- 審査員がその場で選んだ私物を使用できる
- 保存後に物を自由に動かしても、元位置の残像が現れる
- 人が動かすたびに矢印が短くなる
- 正しい位置で吸着するようにチェックが付く
- 最後に現実の机が保存状態へ戻る

## 4. 機能要件

### 4.1 起動・環境確認

**FR-ENV-001 ARCore必須**
- ARCore非対応端末ではインストール対象外とする
- Google Play Services for ARが未導入または古い場合は導入・更新画面へ誘導する

**FR-ENV-002 カメラ権限**
- カメラ権限を初回利用時に要求する
- 拒否時は理由と設定画面への導線を表示する
- 権限なしで空のカメラ画面を表示してはならない

**FR-ENV-003 認証**
- 初回起動時にFirebase Anonymous Authenticationで利用者IDを発行する
- 認証失敗時もAR画面は開けるが、VLM解析開始時に再試行する

**FR-ENV-004 App Check**
- リリースビルドはPlay IntegrityによるApp Checkトークンを付与する
- デバッグビルドは登録済みデバッグトークンのみ許可する

**FR-ENV-005 ネットワーク**
- 保存前にバックエンド到達性を確認する
- VLM解析後のガイド中に通信が切れても、既存の観測結果でガイドを継続する
- 最終確認時に通信が無ければ、成功表示せず「最終確認待ち」とする

### 4.2 ARセッションと品質判定

**FR-AR-001 追跡状態**
- `TRACKING` 以外では保存・復元解析ボタンを無効化する
- 追跡失敗理由を、暗い・速すぎる・特徴が少ない・カメラ競合の4種類へ変換して表示する

**FR-AR-002 水平面**
- 保存には水平面の検出を必須とする
- 対象物体の中心点が同一水平面へ投影可能であることを確認する

**FR-AR-003 座標系**
- 保存時に水平面上へローカル座標系を作成する
- X-Z平面を卓上座標、Y軸を面法線として扱う
- 復元完了まで同じAnchorを保持する

**FR-AR-004 Depth**
- Depth API対応端末では遮蔽表現の改善に利用する
- Depth APIを必須条件にしない
- Depth未対応時は平面とのレイ交差で位置を求める

**FR-AR-005 カメラ設定**
- 背面カメラ、30 FPS優先
- CPU画像は端末が提供する中解像度を優先し、利用不可の場合はVGAへフォールバックする
- 解析用画像と表示用GPUテクスチャを混同しない

### 4.3 保存

**FR-CAP-001 品質ゲート**
保存可能条件:
- ARCoreが`TRACKING`
- 水平面が検出済み
- 画像が著しく暗くない
- 画像が著しくブレていない
- 対象領域が画面の40%以上
- 直近500 msの端末角速度が閾値以下

**FR-CAP-002 対象領域**
- 画面中央に角丸矩形の保存領域を表示する
- VLMへ送る画像は保存領域を中心にクロップする
- 保存領域外はアップロードしない

**FR-CAP-003 撮影**
- 保存ボタン押下時のCPU画像、カメラ姿勢、内部パラメータ、水平面Poseを同一タイムスタンプ系で記録する
- JPEG品質82、長辺最大1600 px、2 MB以下に正規化する
- 画像ハッシュを計算する

**FR-CAP-004 VLM解析**
- 1〜5個の移動可能な物体を抽出する
- 机、床、手、人、影、反射、固定物は対象外とする
- 物体数が0または6以上なら保存を確定しない
- 構造化JSON以外を受理しない

**FR-CAP-005 物体情報**
各物体に以下を持つ:
- sceneObjectId
- label
- visualSignature
- boundingBox
- matchConfidence
- orientationMeaningful
- orientationHint
- symmetry
- exclusionReason
- userConfirmed

**FR-CAP-006 ユーザー確認**
- 番号付き枠と名称を表示する
- 物体単位で除外できる
- 追加の手動矩形選択を1個まで許可する
- 1個以上が確定しなければ保存できない

**FR-CAP-007 世界座標化**
- 物体枠の代表点を水平面へレイ投影する
- 保存位置をAnchor基準のメートル単位で記録する
- 枠の幅・高さから画面上の見かけサイズを記録する
- 位置投影が失敗した物体は保存対象から除外する

**FR-CAP-008 保存確定**
- SceneSnapshotを端末内Roomとアプリ専用ファイル領域へアトミックに保存する
- 保存成功後のみ「好きに動かしてください」へ遷移する
- 途中失敗時に不完全なSceneSnapshotを残さない

### 4.4 現在状態の比較

**FR-CMP-001 復元開始**
- SceneSnapshotが存在する場合のみ「戻す」を有効化する
- 同じARCore SessionとAnchorが`TRACKING`であることを確認する

**FR-CMP-002 現在画像**
- 保存時と同じ領域条件で現在画像を取得する
- 画像品質不良時はVLMへ送らず再撮影を促す

**FR-CMP-003 VLM比較**
- 保存画像、現在画像、保存物体一覧を一度に送る
- 各保存物体について、現在の候補枠、同一物体確信度、状態を返す
- 状態は `aligned / moved / rotated / moved_rotated / missing / occluded / ambiguous`
- 現在のみ存在する物体を`extraObjects`として返す

**FR-CMP-004 対応付け**
- VLMの対応確信度、端末内画像埋め込み類似度、視覚署名の整合性を統合する
- 空間距離を物体同一性の主要根拠にしない
- 対応スコア0.78以上を確定、0.62以上0.78未満を曖昧、0.62未満を不一致とする
- 二つの候補差が0.08未満の場合は曖昧とする

**FR-CMP-005 端末内追跡初期化**
- VLMが返した現在枠とML Kitの検出枠をIoUで関連付ける
- 追跡IDとsceneObjectIdを紐付ける
- 対応できない物体は静的ガイドへ落とし、誤ったリアルタイム追跡を表示しない

### 4.5 ガイド

**FR-GDE-001 一度に1個**
- 同時に複数の大きな矢印を表示しない
- 現在対象を画面上部へ名称とサムネイルで表示する
- 進捗を `2 / 5` 形式で表示する

**FR-GDE-002 優先順位**
1. 他物体を遮蔽している可能性が高い物体
2. 対応確信度が高い物体
3. 目標位置に近い物体
4. missingまたはambiguousな物体

**FR-GDE-003 目標残像**
- 保存時の物体クロップを半透明で目標位置に表示する
- 既定不透明度は28%
- Depth利用可能時は現実物体による遮蔽を反映する
- 追跡不良時は残像を非表示にする

**FR-GDE-004 移動矢印**
- 現在位置から目標位置まで世界座標上の矢印を表示する
- 距離に応じて矢印長を更新する
- 3 cm以内では矢印をリングへ変える

**FR-GDE-005 回転**
- `orientationMeaningful=true`かつ比較結果が回転不一致の場合のみ回転指示を出す
- 時計回り・反時計回りと概算角度を表示する
- 円形・対称物体には回転指示を出さない

**FR-GDE-006 missing**
- 保存時サムネイルと「この物が見つかりません」を表示する
- 見つからない物体について架空の現在位置を表示しない
- 物体が再検出された場合は対応付けを再実行する

**FR-GDE-007 局所完了**
- 目標位置から3 cm以内
- 800 ms以上安定
- 対応確信度0.78以上
- 上記を満たしたら局所完了とする
- 回転が重要な物体は、最終確認まで「位置完了」と表示する

**FR-GDE-008 フィードバック**
- 局所完了時に短いハプティクスとチェックを出す
- 失敗音は使用しない
- 追跡ID喪失時は対象を未完了へ戻し、誤成功を維持しない

### 4.6 最終確認

**FR-VER-001 開始条件**
- 全保存物体が局所完了またはmissing解消済み
- Anchorが`TRACKING`
- 現在画像品質が基準内

**FR-VER-002 VLM最終確認**
- 保存画像と最終画像を比較する
- 各物体の同一性、位置関係、向き、欠落を確認する
- `verified / needs_correction / uncertain`を物体単位で返す

**FR-VER-003 成功条件**
- 全物体が`verified`
- missingが0
- ambiguousが0
- 最終応答のschemaVersionが対応範囲内
- これらを満たすまで`REALITY RESTORED`を表示しない

**FR-VER-004 修正ループ**
- 不一致物体だけをガイド対象へ戻す
- VLMの自然文をそのまま表示せず、定義済み理由コードをUI文言へ変換する
- 1回の復元で最終確認は最大3回
- 3回失敗時は「手動で確認してください」とし、成功扱いにしない

### 4.7 データと同期

**FR-DAT-001 ローカル優先**
- 生画像は端末内を正とする
- Cloud Runは画像を永続化しない
- Firestoreには画像そのものを保存しない

**FR-DAT-002 Firestoreメタデータ**
保存可能:
- sceneId
- uid
- objectCount
- createdAt
- completedAt
- result
- modelId
- latencyMs
- retryCount
- appVersion
- schemaVersion

保存禁止:
- 生画像
- 物体ラベル
- visualSignature
- サムネイル
- プロンプト全文
- VLMの自由文

**FR-DAT-003 削除**
- シーン削除時に端末内画像、Roomレコード、Firestoreメタデータを削除する
- 削除失敗は再試行キューへ入れる

**FR-DAT-004 セッション寿命**
- アプリがバックグラウンドへ移った場合は5分までARセッション復帰を試みる
- OSによるプロセス終了後は復元を再開しない
- 再開不能な保存データは閲覧・削除のみ可能とする

### 4.8 エラーと復旧

定義済みエラーコード:
- `ARCORE_UNAVAILABLE`
- `ARCORE_UPDATE_REQUIRED`
- `CAMERA_PERMISSION_DENIED`
- `CAMERA_UNAVAILABLE`
- `TRACKING_EXCESSIVE_MOTION`
- `TRACKING_INSUFFICIENT_FEATURES`
- `TRACKING_INSUFFICIENT_LIGHT`
- `PLANE_NOT_FOUND`
- `IMAGE_TOO_DARK`
- `IMAGE_TOO_BLURRY`
- `NO_SUPPORTED_OBJECTS`
- `TOO_MANY_OBJECTS`
- `OBJECT_PROJECTION_FAILED`
- `NETWORK_UNAVAILABLE`
- `AUTH_FAILED`
- `APP_CHECK_FAILED`
- `API_RATE_LIMITED`
- `VLM_TIMEOUT`
- `VLM_SCHEMA_INVALID`
- `OBJECT_MATCH_AMBIGUOUS`
- `ANCHOR_LOST`
- `LOCAL_STORAGE_FAILED`
- `FINAL_VERIFICATION_FAILED`

要件:
- すべてのエラーはユーザー向け文言と開発者向けコードを分離する
- 復旧可能なエラーは再試行先を明示する
- バックエンドの内部エラー本文をそのまま表示しない
- 画像や認識結果をログへ出力しない

## 5. 状態機械

| State | 入る条件 | 主操作 | 成功遷移 | 失敗遷移 |
|---|---|---|---|---|
| `INITIALIZING` | アプリ起動 | 認証、App Check、ARCore準備 | `SCANNING` | `BLOCKED` |
| `SCANNING` | AR開始 | 追跡品質・平面探索 | `CAPTURE_READY` | 自己維持 |
| `CAPTURE_READY` | 保存条件成立 | 保存ボタン受付 | `CAPTURING_BASELINE` | `SCANNING` |
| `CAPTURING_BASELINE` | 保存押下 | 画像・Pose取得 | `ANALYZING_BASELINE` | `CAPTURE_READY` |
| `ANALYZING_BASELINE` | 取得完了 | VLM解析 | `REVIEWING_BASELINE` | `CAPTURE_READY` |
| `REVIEWING_BASELINE` | 解析成功 | 対象確認・除外 | `SCENE_SAVED` | `CAPTURE_READY` |
| `SCENE_SAVED` | 保存確定 | 待機案内 | `WAITING_FOR_CHANGE` | `CAPTURE_READY` |
| `WAITING_FOR_CHANGE` | 保存済み | 戻す受付 | `CAPTURING_CURRENT` | `SCANNING` |
| `CAPTURING_CURRENT` | 戻す押下 | 現在画像取得 | `ANALYZING_CURRENT` | `WAITING_FOR_CHANGE` |
| `ANALYZING_CURRENT` | 取得完了 | VLM比較・対応付け | `GUIDING` | `WAITING_FOR_CHANGE` |
| `GUIDING` | 比較成功 | ARガイド・端末内追跡 | `VERIFYING` | `RECOVERING` |
| `VERIFYING` | 局所完了 | VLM最終確認 | `RESTORED` | `GUIDING` |
| `RESTORED` | 全体確認成功 | 成功表示・リセット | `SCANNING` | - |
| `RECOVERING` | 追跡・通信一時障害 | 復旧案内 | 直前状態 | `BLOCKED` |
| `BLOCKED` | 継続不能 | 設定・終了・削除 | 条件により`INITIALIZING` | 自己維持 |

状態変更は単一のReducerを通し、画面から直接ドメイン状態を書き換えない。

## 6. 非機能要件

### 6.1 性能

- 参照端末: Pixel 8
- カメラ背景描画: 30 FPS目標、20 FPS未満が1秒以上続かない
- ガイド位置更新: 15 Hz以上
- UI入力反応: 100 ms以内
- 端末内物体追跡処理: 1フレーム100 ms以内
- Rustコア判定: 1回10 ms以内
- 通常フローのVLM呼び出し: 3回
  - baseline
  - compare
  - final verify
- 回復用追加呼び出しを含め最大6回
- VLM APIのクライアント側締切: 12秒
- 429および5xxのみ1回再試行
- リリースAPK/AABのダウンロードサイズ目標: 120 MB以下
- ピークメモリ目標: 350 MB以下
- 画像アップロード: 1枚2 MB以下、1リクエスト4.5 MB以下

### 6.2 精度

検証セットにおける完成条件:
- 対応物体検出率: 90%以上
- 同一物体対応精度: 90%以上
- missing検出適合率: 95%以上
- 位置復元成功: 90%以上
- 成功判定の偽陽性: 2%以下
- 対応可能な物体での最終成功率: 85%以上
- 位置誤差中央値: 3 cm以下
- VLM構造化出力の初回Schema適合率: 98%以上
- 1回再試行後のSchema適合率: 99.5%以上

### 6.3 信頼性

- 画像、ARCore Image、Depth Image、PointCloudは取得元スレッドで必ずcloseする
- 同一sceneIdとIdempotency-Keyの重複リクエストは同じ結果を返す
- バックエンド障害時に不完全なSceneSnapshotを保存しない
- 画面回転は縦固定とし、Activity再生成でセッション状態を失わない
- プロセス終了は明示的に非対応とし、誤った再開をしない

### 6.4 セキュリティ

- モバイルへVertex AI認証情報を埋め込まない
- Cloud RunはFirebase ID tokenとApp Check tokenを検証する
- Cloud Runサービスアカウントへ必要最小限のIAMのみ付与する
- 画像MIMEはJPEG/WEBPのみ
- 画像デコード前にContent-Lengthを検査する
- デコード後の最大画素数を制限する
- VLM出力をJSON Schemaで検証する
- 画像内文字列を命令として扱わない旨をSystem Instructionへ明記する
- モデルに外部ツール呼び出し、URL取得、コード実行を許可しない
- PIIをログ・分析イベントへ含めない
- `android:allowBackup="false"`を既定とする

### 6.5 プライバシー

- 保存領域外をアップロードしない
- Cloud Runでリクエスト本文ログを出さない
- 画像をCloud Storageへ自動保存しない
- デバッグ画像保存はDebug buildのみ、端末内、24時間で削除
- Firestoreへ物体ラベルを送らない
- 利用者がシーンを削除できる
- 利用規約画面で、解析画像がVertex AIへ一時送信されることを明示する

### 6.6 アクセシビリティ

- 操作領域48 dp以上
- 色だけで状態を伝えない
- 残像、矢印、文字、ハプティクスを併用する
- TalkBack用contentDescriptionを主要操作へ付与する
- 日本語を既定、文字列はAndroid resourcesへ分離する
- 成功アニメーションは「動きを減らす」設定で短縮する
